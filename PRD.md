### 18. Motion Requirements
Controlled, purposeful motion only. Possible uses: hero entrance, section transitions, project cards, navigation, theme switching, hover states, project media, scroll reveals. Must respect reduced‑motion preferences and not hinder readability/accessibility.

---

### 19. Responsive Requirements
First‑class mobile experience. Must work on phones, tablets, laptops, desktop monitors. Navigation, cards, certificates, media, forms, creative gallery must remain practical on small screens.

---

### 20. Accessibility Requirements
Aim for WCAG 2.1 AA where practical:
- Keyboard‑accessible navigation, visible focus states
- Sufficient contrast (both themes)
- Semantic hierarchy, alt text for images
- Accessible forms
- No critical info conveyed by color alone
- Respect reduced‑motion preferences

---

### 21. Performance Requirements
Fast experience on average mobile connections. Strong Core Web Vitals, Lighthouse scores. Optimize large images (certificates, project screenshots, portrait). Advanced effects must not compromise core browsing.
